Three Lenses, One Customer
CRM measures handling-quality after a case is opened — "did RTA resolve my issue well?" Social measures lived-experience as it happens — "how was the service in the wild?" Google reviews are place-anchored and star-rated — "was this specific facility worth my time?" All three numbers below are correct; they capture different moments and different customers. The gaps between them are the value of triangulating all three.

— Methodology
CRM-side figures are computed directly from the four CRM exports (2023–2026, n = 100,921). CSAT is the satisfied-share of the 59,710 cases with a post-resolution rating. Dissatisfaction drivers are the most frequent Reason/Purpose values among cases tagged Dissatisfied or Very Dissatisfied (n = 1,584). Valid-complaint reasons are reported separately because they capture experience-driven volume, not just resolved-case ratings.

Social-side figures use the live social listening backend in this build — adapters for X, Meta, Reddit, and RSS news. The current view samples 12 representative mentions in demo mode; once credentials are configured (see INTEGRATION.md), the same widgets refresh automatically with live volume.

Google-side figures use the Google Places API adapter. The API returns up to 5 most recent reviews per place, so production pulls cycle through ~30 monitored Dubai locations (taxi stands, nol top-up centres, marine stations, bus stations, customer happiness centres). Star ratings are mapped to a normalized sentiment score (1★ → −1.0, 5★ → +1.0); free-text reviews additionally pass through the same lexicon/LLM classifier as the rest of the social sources. Currently sampling 6 demo places. Estimated production cost at RTA volume: ~$5/month.

The unified taxonomy maps both sources to the same five root-cause categories using keyword + reason-code rules. The gap column (social% − CRM%) is the headline diagnostic: positive = under-counted by CRM, negative = over-represented in formal channels.

Language detection uses Unicode range matching: any character in U+0600-U+06FF marks Arabic content; Latin character runs of 4+ chars mark English. Bilingual cases contain both. Per-service splits are computed from the Case Description field of the 100,921 CRM cases — that's the customer's own words, unlike the structured Reason/Purpose codes which are English-only Power BI dimensions. Arabic share varies meaningfully by service (Taxis 33%, Bus 21%, nol 18%) and matches Dubai's resident-vs-expat usage patterns.

Action-plan scoring follows the brief's "effectiveness AND efficiency" requirement. Effectiveness = expected reduction in the underlying root cause volume. Efficiency = cost-time-resource burden, scored inversely (5 = low burden, 1 = high). Priority is independent of either — it ranks the cause itself by aggregate volume, not the action.
